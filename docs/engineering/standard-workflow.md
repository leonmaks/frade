# Frade direction workflow

Status: `NOT_DEPLOYED_W01_CLOSURE_PENDING`. This text instantiates the accepted W01 design for engineering use. W01 checks, Verify, POST and closure still require actual evidence. Common review release v1.1 remains immutable. Writer dispatch is `NOT_IMPLEMENTED`.

A direction is an owned objective with one immutable original baseline, registered `codex/<id>` branch/worktree, approved scope and exact remote/ref. Stages contain tasks and ordered steps; legacy R/P stage IDs and history remain intact. Phase, health, applicability, publication and adoption are separate facts.

The phase order is `INTAKE → RESEARCH → REQUIREMENTS → PLANNING → PRE_REVIEW → BDD_TDD → IMPLEMENTATION → CHECKS → VERIFICATION → POST_REVIEW → ARCHIVE → CLOSED`. A small feature can use one stage, with the same barriers. The agent inventories the repository and exact owner first, prepares proposal/spec/design/tasks and a check plan, obtains required material decisions, then performs current independent PRE, deterministic RED, scoped implementation and actual applicable checks. Formal Verify and current independent POST follow checks; only then may the owner consider exact sync/archive. Starting the next numbered direction or integrating into main requires its own authorization.

The registered owner manifest lives at `docs/engineering/directions/<id>/direction.json`. The root loader selects it from the real Git branch/common and target path. Its rule result includes root, owning direction and path nested `AGENTS.md` contracts. Every contract remains in force; the loader does not interpret prose as equivalent and does not grant writes. Existing root sections 1–17, Routing V2 contracts and other applicable product contracts remain mandatory. Existing lifecycle, scope, review and closure controls make separate executor admission decisions; a loader result never substitutes for those current gates. A future closure flag causes the loader to report `CLOSURE_ADMISSION_NOT_EVALUATED`, leaving the actual closure decision to those controls.

For every stage, declare required general and subsystem checks before execution. Record command, exit, source/config/environment, raw evidence and accepted limit. `REQUIRED` failures and unavailable checks block closure. `NOT_APPLICABLE` needs a contract reason and unchanged affected tree proof before execution; an applicable failure cannot become N/A. Process-only W01 runs direction controls, strict OpenSpec validation, root lint/type/build/boundary checks and content/hash/link/frozen audit. Product `check:all` remains `NOT_RUN` until executed; no product GREEN is inferred from control checks.

The approved task or role assignment resolves to exactly one model and effort. Provenance records approved assignment, invoked pair and confirmed backend, or `NOT_CONFIRMED`. Reviewer PASS requires its independent confined transport; an owner or writer cannot self-approve. Shared writer dispatch remains unavailable.

Keep an eight-block status in this order: decision/next step; identity/scope; roadmap; active tasks/steps; checks/gates/quality; models/execution; dependencies/decisions/blockers; Git/publication/evidence. Task counts are administrative progress. Keep historical FAIL and immutable receipts. After a tested task or significant checkpoint, publish only to the previously authorized feature ref using the checkpoint protocol and verify fresh remote SHA. A blocker checkpoint is labeled incomplete. Neither publication nor a completed checklist grants Verify, POST, closure, consumer adoption or main merge.

Routing, UI and Repo Core adopt separately in their own worktrees, preserving origins and frozen contracts. A completed legacy checklist without formal closure is `IMPLEMENTED_PENDING_CLOSURE`. Main integration revalidates the actual merged candidate and needs its own permission.
