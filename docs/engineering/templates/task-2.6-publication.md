# Direction checkpoint and publication

Use the canonical public CLI after the review freeze is released:

```text
node scripts/directions/cli.mjs checkpoint <absolute-direction.json> <absolute-event.json>
node scripts/directions/cli.mjs publish <absolute-checkpoint-receipt.json>
```

The event file is an input record, not an approval. It has `kind` (`TASK`, `PLANNING`, `GATE`, `STAGE`, or `BLOCKER`), `health`, `message`, exact `paths`, and nonempty `evidence` entries containing `path` and raw SHA256. A task event also has its task ID. Include the tracked status path and new raw evidence. A blocker must say `FAIL` or `BLOCKED` in the status and evidence. A receipt alone cannot cause a checkpoint.

The controller provisions `<git-common>/frade-workflow/publication-authority/<direction-id>.json` outside the owner request. Schema version 1 binds the manifest owner, immutable `originalBaseline`, `approvedSourceCommit`, exact `remote` and feature `ref`, `requiredChecks` (unique check IDs), and separate `approval` and `plan` objects with repository paths and SHA256. The approved source commit must descend from the original baseline and precede the current HEAD. The raw D02 decision at that commit must contain the exact approved remote/ref and direct reply. The approved plan must contain the same target and checkpoint cadence; current source bytes must still match. The owner manifest's publication flags and the event's destination strings grant no authority.

For `TASK` and `BLOCKER`, the controller also provisions `<git-common>/frade-workflow/publication-admission/<direction-id>/<event-sha256>.json`. Schema version 1 contains `id`, `kind`, `task` (task ID for `TASK`, `null` for `BLOCKER`), `sourceHead`, `manifestSha256`, `authoritySha256`, `eventSha256`, `candidateSha256`, and `checks`. `candidateSha256` is SHA256 of the concatenation of each sorted event path, NUL, SHA256 of its current raw bytes, and LF. Each check has an authorized `id`, actual `argv`, raw process `exitCode`, `result` (`PASS` or `FAIL`), and `raw: { name: "<id>.log", sha256 }`. The controller writes the actual unmodified check output with its command and exit record under `<git-common>/frade-workflow/publication-checks/<direction-id>/<id>.log`, then binds the log bytes in the admission. These records must be produced from current mandatory native checks for the exact source and candidate before checkpoint. An owner event or owner evidence JSON that says PASS cannot provision admission. A task needs all authorized checks with exit 0 and PASS; FAIL or BLOCKED task health is rejected. A blocker needs at least one actual failed check with raw failure and blocked status, and cannot grant tested-task cadence, GREEN, Verify, or closure. Formal Verify and POST are separate later barriers, not prerequisites for publishing a completed tested implementation task.

Checkpoint checks the registered owning branch/common, freeze lock, scope, every worktree and index path, raw evidence hashes, secret patterns and nonempty new evidence before exact pathspec staging. It validates the actual `origin` fetch and push URLs, exact branch upstream, and absence of repository-local URL rewrites before remote operations. It preserves unrelated files and rejects an occupied index. The result is `CHECKPOINTED`, with the commit SHA and an immutable receipt under Git common storage. It does not assert GREEN, Verify, POST, closure or remote publication.

The default public CLI is bound to Frade's canonical Git common (`E:/dev/codex/frade/.git` on Windows, `/mnt/e/dev/codex/frade/.git` in WSL) and also checks the module's registered worktree/common before reading owner authority or admission. The manifest, event, receipt, current directory, and environment cannot select another control root. A copied CLI in a foreign checkout with matching-looking authority and admission JSON is rejected. Path checks resolve the owner root and each descendant with the platform path rules, reject traversal and sibling roots, and check each existing component's canonical path to reject symbolic links and Windows reparse paths. Disposable bare-remote positives call the copied module API with `trustedPublicationFixtureContext(common, { brand: 'FRADE_PUBLICATION_TEST_CONTROLLER_V1' })` and pass the returned `trustedContext` to `checkpoint` or `publish`; the public CLI does not accept that context. Native childprocess tests cover public CLI rejection for both the original and copied foreign entry. The owning controller separately verifies the installed CLI on the authorized W01 owner.

Publish requires the exact local checkpoint SHA at HEAD. It queries the authorized remote feature ref, checks ancestry, pushes `<checkpoint-SHA>:<exact-ref>` once without force, then independently queries the remote again. Only an exact fresh SHA match produces `PUBLISHED`. Failed push, unavailable transport, divergence and mismatched SHA remain `BLOCKED` with local work retained. The publication receipt stores raw Git argv, status, signal, reported spawn error, exit code and output outside the candidate. A reported spawn error or signal blocks publication even if the process status is zero; no synthetic exit code replaces the raw status. A second publish attempt for the same SHA is refused. Recovery keeps the blocked receipt and its failed commands, diagnoses the transport or remote mismatch, and creates a new coherent checkpoint with new status/evidence and fresh controller admission. Its new SHA can be published once after the destination is corrected; a successful push discovered after a post-push mismatch still requires an explicit new checkpoint rather than a hidden retry or a false PUBLISHED claim.

After publication, refresh the tracked status at the next natural task, plan, gate, stage or blocker checkpoint. Copy the prior immutable publication receipt into scoped evidence, set `previousPublicationReceipt` to the prior checkpoint SHA, and record both prior source and verified remote SHA in status. The receipt joins that next checkpoint; it never triggers a receipt-only commit. Formal Verify, current independent POST and closure barriers remain separate.

For W01 the production target is `git@github.com:leonmaks/frade.git` at `refs/heads/codex/frade-standard-workflow` only. This worker's tests use disposable local bare remotes. The actual production authority record and live GitHub invocation belong to the owning controller.
