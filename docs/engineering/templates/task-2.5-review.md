# W01 task 2.5 review adapter

The adapter in `scripts/directions/review.mjs` consumes the installed, immutable Frade v1.1 shared runner. It does not change its transport or publish a new shared release. The public CLI currently admits only the registered W01 owner in the canonical Frade Git common directory:

```text
node scripts/directions/cli.mjs review/prepare <absolute-installed-manifest> PRE|POST <absolute-external-request.json>
node scripts/directions/cli.mjs review <absolute-installed-manifest> PRE|POST <absolute-external-request.json>
```

`review/prepare` is a structural and provenance preflight. `review` also runs actual strict change and all-spec validation, verifies the current shared pointer and every declared bundle file against the approved raw bundle hash before loading executable release code, freezes the candidate, invokes the shared physical PRE or POST runner in a dedicated child, retains raw material, and checks the complete event stream and final report. The child inherits `GIT_OPTIONAL_LOCKS=0` and scoped Git configuration while the parent binds the raw index before and after. A focused task diagnostic sets `focused: true`; its PASS is retained as scoped evidence and `closureAuthorized` remains false. Formal Verify is a separate phase and is never called POST. A valid review FAIL stops the owning scope. Codex raw exit 0 means clean transport for PASS and FAIL; the wrapper CLI exits 0, 1, or 2 for PASS, FAIL, or BLOCKED. Unavailable runtime, changed source or invalid reception is BLOCKED.

Strict validation discovers the installed public `@fission-ai/openspec` 1.14.0 package from the owner local package or an npm shim directory on `PATH`. The adapter checks the package identity and bin entry, then launches the verified JavaScript entry with `process.execPath` and fixed argv. It does not execute a Windows `.cmd` shim or use a shell. Raw receipts bind the Node executable, package and entry hashes, shim discovery, actual launch argv, semantic OpenSpec argv, output and exit. Both JSON outputs must report complete valid items and include the selected change; a zero exit alone is insufficient. Unknown, ambiguous or changed toolchains block review. The Windows launch argv therefore names Node and the JavaScript entry; `openspec` in the receipt denotes the semantic CLI command.

The external request names `phase`, `stage`, a numeric task such as `"2.5"`, matching `taskType` and `role` (`independent-PRE` or `independent-POST`), the stage's exact `change`, an exact `scope`, `focused`, explicit relative `paths`, and a complete `prompt`. It contains no approval or model fields. For W01, the plan's exact role row supplies Astra/xhigh. The W01 controller adapter binds the raw design SHA, unique row excerpt and D03 revision to the separate D03 plan decision and user-decisions hashes. It requires the approved proposal, design and three delta specs, current tasks, adopted policy, decisions, D03 and tracked status in the packet. The manifest must carry `stage.roleAuthority` with the exact design path/hash, revision `D03`, and D03 decision path/hash. The illustrative draft manifest has invalid scope annotations and does not become installed authority by being copied.

Reusable preparation, production reception, fixture reception, freeze and strict validation accept another direction only through a host-created `createReviewAdmission` object. The host supplies a trusted role authority, independently bound policy hash, allowed scope, mandatory packet paths and a verifier of independent plan approval. The request and manifest cannot create that object or grant approval through JSON fields. The current public CLI registers W01 alone; an unknown owner is BLOCKED. A future owner needs an explicit host adapter with independently checked approval bytes, source bindings and owner scope, plus a reviewed CLI registration. This is a supported core boundary, not a completed owner migration or a universal model default.

The freeze marker is `<Git common>/frade-workflow/freeze/<direction-id>.json`; its record separately binds the owning stage and change. All stage changes under that direction contend for the same marker, and `refreshStatus({ write: true })` returns `FROZEN` without changing the status file while it exists. Common-scoped runs retain the before snapshot (all tracked and nonignored files, status bytes, raw index, HEAD), request and plan bindings, packet files/hashes, strict validation raw outputs/exits, shared raw run tree, original events/report/stderr/exit, wrapper result and deferred review event. Raw capture inventories every copied file with source and copy hashes and checks the source again. At most four direct directory links under the canary-only `offline-home/tmp/arg0` path are retained as exclusion metadata; Windows junctions and Linux directory symlinks are checked as real reparse/link entries. These bounded runtime-home entries are not reviewer evidence. Links in output, packet, instance or any other location block reception, including an unknown output link. The status writer defers while the marker exists. The wrapper removes it only after raw reception and final unchanged owner verification; a mutated or unavailable owner keeps the marker for investigation. The deferred event is outside the candidate and can be projected after unfreeze. Reviewer execution does not write the candidate.

The disposable test transport is a separate branded, hash-checked API used by `runFixtureReview`. The public CLI and `runProductionReview` never accept that transport. Its assertions exercise the same wrapper source, snapshot, packet and raw-verdict checks using private temporary Git repositories. It does not attest a live reviewer, actual backend/effort, Windows canary or shared service availability. `actualBackend` and `actualEffort` stay `NOT_CONFIRMED`; only the invoked exact args and shared canary can establish the requested execution path.

The packet completeness test copies the current public review test module into its disposable Git fixture and selects it with the mandatory W01 sources. Its known-fake credential negative control composes the key and value at runtime, preserving the original 36-byte file content and the `REVIEW_CREDENTIAL` rejection without placing a credential-shaped literal in selected public test source.

The pinned bundle check runs before loading executable shared release modules. The fixture also places the complete bundle behind a real parent-directory link so `core.mjs` escapes through that parent; Windows uses a directory junction and Linux uses a directory symlink. The untouched copied shared `core.mjs` and `transport/integrity.mjs` have fixed raw hashes and local `-text` Git attributes. Their child test invokes the real modules with the normal Node child-process library and verifies the candidate index remains byte-identical. A Linux sandbox that denies the shared core's synchronous Git child call cannot establish this test's PASS; the native Windows run is the authoritative execution check.

Task 2.5 requires a fresh actual W01 diagnostic invocation. The parent controller can provide a temporary external manifest derived from W01's accepted D03 owner, role matrix and scope, and a separate external request. That manifest is a bounded diagnostic input, not product loader installation or task 2.7 completion. The parent freezes current source/status/index/HEAD, checks the unchanged shared release and fresh offline canary, then invokes the public CLI with exact Astra/xhigh and retains raw events, report and exits. The isolated Linux worker has no registered W01 owner or Windows reviewer runtime, so this invocation must be performed by the parent before task 2.5 is complete. A focused PASS remains diagnostic evidence and grants no cumulative Verify, final POST, archive or closure.
