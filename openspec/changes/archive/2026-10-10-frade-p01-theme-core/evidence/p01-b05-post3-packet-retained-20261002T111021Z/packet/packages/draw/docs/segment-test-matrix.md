# Матрица редактирования floating-связей прямоугольников

## Область проверки

Автоматизированы описанные пользователем движения для двух прямоугольников.
Матрица не является доказательством всех возможных диаграмм: произвольные контуры,
fixed ports, перекрывающиеся фигуры и произвольное количество препятствий требуют
своих сценариев. Эти случаи не объявляются покрытыми данной матрицей.

Основная fixture: A=(80,80,120,80), B=(500,280,120,80).
Для фигур на одном уровне B.y=80. Координаты используются только в тестах.
Production-алгоритм не содержит этих координат и не проверяет имена A/B.

## Комбинации

| Расположение A относительно B | Направления |
| ----------------------------- | ----------- |
| Выше и левее                  | A→B, B→A    |
| Ниже и левее                  | A→B, B→A    |
| Выше и правее                 | A→B, B→A    |
| Ниже и правее                 | A→B, B→A    |
| На одном уровне, левее/правее | A→B, B→A    |
| На одной вертикали, выше/ниже | A→B, B→A    |

Генератор `tests/spike/support/symmetry.ts` применяет отражения X/Y,
перестановку X↔Y и обращение направления связи. Перестановка меняет также
ширину/высоту фигур и направление движения мыши. Имена фигур сохраняются.
Всего 16 преобразований каждого сценария, включая две ориентации прямоугольников.

Итого: **160 browser integration scenarios**, использующих настоящие mouse events,
production graph и SVG. Создание fixtures и выбор связи выполняются test API;
это не полный application E2E создания диаграммы через палитру.

Каждое применённое промежуточное положение проверяет: ортогональность,
отсутствие самопересечений, наложений, разворотов на 180°, пересечения внутренних
областей обеих фигур, правильный выход/вход на контуре, наличие сегмента на
запрошенной координате, существование SVG и сохранение stroke/markers/dash.
После pointerup геометрия сравнивается с последним кадром drag.
Маршрут перед валидатором не упрощается так, чтобы можно было скрыть петлю.

Прежние `floating-top-entry`, `floating-horizontal-entry`, `floating-cross-terminal`
сохранены. Последний отдельно проверяет повторное выделение перед границей и на ней.

## Общий алгоритм и обнаруженные дефекты

`src/segment-editing/resolveSegmentDrag.ts` — pure resolver в локальных осях
выбранного сегмента. Для вертикального сегмента оси меняются местами;
направление source/target не влияет на геометрическую политику.
Терминальный сегмент сначала сохраняет соседнюю геометрию. Внутренний коридор
пересчитывает floating terminals. Если коридор пересекает противоположную фигуру,
её старое подключение освобождается и оба конца разрешаются совместно.
Препятствие не разрешается пересекать: если допустимого кандидата нет,
X6 adapter сохраняет последнюю принятую геометрию. Это не новый obstacle router.

Проверки воспроизвели до исправления:

- обратные участки и самопересечения при B→A;
- лишние обходы прямой связи при aligned расположении;
- поворот горизонтальной ручки на 90° из-за погрешности X6 getClosestPoint
  на обратном rounded path;
- замораживание или проход сквозь противоположную фигуру после смены топологии.

`tests/unit/segment-symmetry.test.ts` дополнительно проверяет точное равенство
преобразованных маршрутов после отражений, транспонирования и обращения связи,
точные границы и дробные координаты, отказ при препятствии и отсутствие мутаций.

## Запуск и визуальные эталоны

- `pnpm --filter @frade/draw test:visual:matrix` — только 160 сценариев матрицы.
- `pnpm test:e2e` — вся Chromium-регрессия, включая прежние screenshots.
- `npm test` — unit/BDD и метаморфные проверки solver.
- `pnpm build` — TypeScript и production-сборка.

При падении Playwright сохраняет trace и screenshot. Обычный запуск эталоны не меняет.

Осознанное обновление эталонов после просмотра diff:
SEG-VIS-004 и SEG-VIS-009 теперь показывают подключение к нижним граням вместо
прежнего ненужного обхода внешних боковых граней aligned-фигур. Перед screenshot
есть явные assertions точек подключения. SEG-VIS-005 отражает точное размещение
ручки и terminal на логическом контуре без субпиксельной коррекции X6.
Порог screenshot comparison не увеличивался.

## Обход фигур по окружности

`tests/spike/floating-orbit.spec.ts` добавляет 16 сценариев ORBIT:
движущаяся фигура A/B × начальное направление обхода × направление связи A→B/B→A
× исходная/предварительно отредактированная связь. Фигура перемещается настоящими
mouse events при удержании кнопки; один сценарий проходит круг с шагом 15° и затем
обратно. Проверяются 48 положений в каждом сценарии, все стороны контура,
отсутствие пересечения обеих фигур, ортогональность, отсутствие возвратов/петель,
скругления реального SVG и совпадение маршрутов при повторном посещении позиции.
В положениях на одной горизонтали или вертикали маршрут должен быть прямым.
Проверяется также сохранение геометрии после отпускания мыши.

Перемещение/resize теперь разрешает оба floating terminals заново и передаёт
в X6 полностью проверенную полилинию с точными anchors. Старые anchors ручного
редактирования и вторичный Manhattan reroute больше не смешиваются с ней.
Исходное создание связей, fixed ports и непрямоугольные фигуры этим обработчиком
не изменяются. Круговые fixtures не перекрывают тела фигур.

Эталон SEG-VIS-007 обновлён отдельно после просмотра expected/actual: после
перемещения source маршрут теперь входит в ближнюю левую грань target вместо
лишнего обхода снизу. Перед screenshot проверяются валидность маршрута, точные
endpoints (370,95) → (620,255) и направление входа. Допуск сравнения не изменён.
Production visual tests явно ожидают установки FRADE_VISUAL_TEST перед обращением
к API, устраняя гонку загрузки страницы при полном параллельном прогоне.

Контрольный прогон после исправления кругового движения:

- `npm run test:visual`: 192 passed, без обновления эталонов.
- `npm test`: 179 passed (25 файлов).
- `npm run build`: PASS; предупреждение Vite о размере bundle сохраняется.
- `openspec validate --specs --strict --no-interactive`: 4 passed.

## Клик по magnet уже соединённой фигуры

`floating-magnet-click.spec.ts`: 6 сценариев — клик по A/B для исходной связи,
после перемещения фигуры и после ручного изменения сегмента. Проверяется точное
равенство реальных сегментов и SVG до нажатия, во время нажатия и после отпускания;
временное ребро не должно оставаться в графе. До исправления два сценария после
перемещения воспроизвели диагонали уже на pointerdown (RED).

Причина: edge:added временного ребра пересчитывал все связи, смешивая новые
vertices со старыми anchors. Теперь событие обрабатывает только добавленное ребро.
Итог: 198 Chromium tests и 179 unit/BDD checks прошли; build и 4 OpenSpec specs
валидны. Скриншотные эталоны в этом исправлении не обновлялись.

## Размещение посторонних фигур

`floating-placement.spec.ts`: четыре сценария (исходная связь / после перемещения
endpoint × новая фигура рядом / поверх маршрута). После добавления, настоящего
mouse drag и resize проверяется точное равенство логических сегментов и SVG path.
Все четыре сценария сначала падали: изменение любой фигуры запускало глобальный
reroute. Теперь position/size events пересчитывают только связи этой фигуры.
Перекрытие готовой связи посторонней фигурой допускается без перестроения.

Полный контрольный прогон: 202 Chromium tests, 179 unit/BDD checks, build и четыре
OpenSpec specs прошли. Скриншотные эталоны не менялись.

## Палитра после соединения мышью

`palette-placement.spec.ts` воспроизводит основной UI без загрузки готовой связи:
два нажатия rect, перемещение второго прямоугольника за подпись, соединение
настоящим mouse drag к центру второй фигуры, добавление третьей фигуры поверх
первой. Пять вариантов охватывают все кнопки палитры. Сравниваются реальные
сегменты, SVG path, координаты и размеры исходных фигур.

RED воспроизвёл переход связи с правой грани на верхнюю после третьего rect.
Причина отличия от fixture-тестов: интерактивное ребро добавляется с незакреплённой
целью и оставалось на автоматическом Manhattan-router после соединения.
Теперь edge:connected разрешает оба terminal и фиксирует рассчитанную полилинию;
перерисовка после добавления фигуры не запускает для неё новый поиск маршрута.
