### Token pipeline

Adapt the supplied Python generator to a Node module used by both generate and check commands, because every CI job already provisions Node/pnpm and no Python step exists. Preserve role IDs, declared order, token version `1.0.0`, palette values, density, coarse-pointer and reduced-motion semantics and all 34 named contrast pairs per theme (102 total). Frade CSS adoption revision 1 permits exactly one automatic-Dark selector correction: `:root:not([data-frade-theme])` becomes `:root:where(:not([data-frade-theme]))`; original input bytes remain immutable. This enforces the already required final forced-colors mapping with no theme attribute as well as explicit System/Light/Dark/HC. The equivalence oracle is the original LF/UTF-8 CSS with exactly that one replacement, checking its source occurrence count and every remaining byte. Any additional discrepancy fails. Record source hashes, accepted exception/revision and review provenance in canonical adoption documentation; keep revision metadata separate from CSS bytes so no second CSS deviation is introduced. Produce CSS and typed TS roles deterministically with LF/UTF-8 and no dates. Generator check computes output in memory and compares both artifacts without rewriting them. Version mismatches, missing/extra roles, malformed HEX, nonfinite values and drift fail with paths and IDs. Source palette changes require separate contract review. The accepted decision is `decisions/token-css-adoption-2026-09-30.md`.

Foundation owns standalone generated-CSS cascade tests in `apps/desktop/tests/e2e/ui-contract-token-cascade.spec.ts` using the existing Playwright dependency. The approved foundation PRE scope is limited to loading generated CSS in an isolated document; it does not launch or migrate the workbench, install a runtime resolver or write repository data. Run RED against the unchanged source before the Node-generator repair; then run approved generated CSS against the full 20-state matrix (OS Light/Dark × forced-colors on/off × no attribute/System/Light/Dark/HC), asserting every theme role on root and an inherited child and confirming media emulation is active. Non-forced controls preserve the original palette; forced controls assert the declared system-keyword mapping. P01 still owns actual runtime root/portal/canvas integration and accessibility evidence. Existing desktop Playwright `testDir` already covers this path; the Windows job must execute this narrowly scoped test alongside its existing checks.

Feature literal checking covers CSS/TS/TSX in renderer/workbench/navigator/inspector/Draw presentation, including HEX, rgb/hsl/named colors and inline styles. Use an explicit versioned inventory of preexisting violations with file/span/value/hash/reason/stage; changing a legacy occurrence invalidates its exemption. Allowed data boundaries: validated theme data, generated outputs, test fixtures, user-authored diagram paint/default domain visualization and sanctioned brand data. Domain exceptions are symbol/field scoped, not whole-file exemptions for `FradeDiagramView.tsx`. A negative feature fixture must fail; generated/theme data must pass; drift must fail. Fixtures live under validated OS temp roots and are removed in finally, retaining only result/hash evidence.

### One theme service, both palettes

Foundation does not install a second static runtime selector. P01 owns complete resolver/registry/preview and root integration; shipping a Dark-only milestone or CSS masquerading as hot ThemeService is prohibited. Builtins Light/Dark/HC are loaded locally before first paint. Explicit kind outranks OS preferences; forced colors maps to system colors last. Density is persisted independently. Preferences store validated versioned user presentation data, never document geometry or draft state. Electron settings adapter is host-owned; malformed settings use fallback diagnostics. Workspace overrides are opt-in and never install or execute packages.

P01 prepare-all/commit/rollback participants include root/portals/X6 and the embedded Draw.io adapter. An adapter refusing preparation blocks the complete transaction; no successful shell-only partial commit. Snapshots are immutable, monotonically revisioned; late candidates lose to the newest generation. Persist only after all participants commit; persistence failure restores prior settings/snapshot. Preview is transient; Esc/outside/window-close restores committed state; Enter commits. Layout, document identity, undo, dirty editors and selections survive. No theme transaction calls repository writes or serializes UI selection into documents. Native `diagram.*` roles apply to transient canvas/chrome only; stored appearance and semantic palettes remain separate.

## Risks / Trade-offs

- Shared-file/process collisions → isolated worktrees, serialized merges and consumer-owned revalidation; no R04 repair/closure predecessor for UI.
- Old WB-001 visual contract → user-accepted full replacement with explicit supersession ownership; migration baseline approval remains a separate checkpoint.
- Embedded canvas/iframe lag → required atomic adapter handshake; preserve document bytes and dirty state, fail/rollback rather than partial success.
- Existing large legacy literal surface → auditable occurrence inventory with stage closure; no blanket skip.
- Shared-package import cycles → narrow leaf export and existing boundary tests before component dependency changes.
- Input ZIP engines target 1.0 while application is 0.1 → fixture rejection/migration in P02, no version bump or implicit compatibility claim.
- Emotional design hypothesis → qualitative user research is separate NOT_RUN evidence, never fabricated retention results.
