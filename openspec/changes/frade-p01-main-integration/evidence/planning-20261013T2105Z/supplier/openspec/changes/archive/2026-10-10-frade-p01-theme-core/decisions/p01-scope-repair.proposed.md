## Exact replacement for design runtime decisions

1. **Resolver / registry.** Import existing generated palettes without changing them. Builtin stable IDs frade.builtin/light, frade.builtin/dark, frade.builtin/high-contrast; registry reserves these immutable offline entries. External in-memory descriptors are validated data, not installed packages. Stable publisher.name/local IDs do not depend on version/path/label. Native input accepts known role IDs and HEX6; unknown roles are diagnostic-only and never injected. Invalid values produce explicit issues without arbitrary CSS. Use all 31 roles and the existing fixed 34 contrast-pair definitions; a runtime pure constraint table must be compared to the unchanged foundation table, not diverge. Precedence builtin -> enabled selected descriptor -> user global -> selected ThemeId override -> explicitly enabled workspace override. Fixed pair order restores both roles from builtin for at most ten passes, then full builtin FALLBACK. Inputs remain unmutated; outputs/diagnostics copied and deeply frozen. Density is separate. Forced-colors final system keyword mapping overrides presentation values even with explicit Light/external overrides; do not persist system keywords as user HEX. Installed-package enable/remove/version lifecycle remains P02.

2. **Persistence / startup.** One user/profile settings DTO (version 1) stored in a fixed userData presentation-settings.json, with theme System by default, preferredLight/Dark/HC IDs and density compact by default. Profile here means the existing selected Electron userData root; P07 owns multi-profile management. Opt-in workspace override is resolver data only, with no automatic workspace file reads or writes and no trust escalation. Unknown/stale IDs repair to offline builtin of kind with diagnostics, not a phantom installed theme. Main validates every DTO before and after IPC; separate channel/exposure preserves the existing window.frade health keys. Authorize the existing window/main frame/trusted page; deny child frames, forged revisions, arbitrary paths, unknown fields and oversized payloads. Serialize commits using host revision/CAS. Write a fixed-path staged file, flush and atomic rename; prepare must never replace current settings. On write failure read back authoritative state and restore old persistent/presentation selection; report unknown outcomes instead of falsely claiming rollback. Startup reads/validates before showing the window; initialize builtin/root metadata before first app paint, restore valid user selection before showing normal UI, default with visible diagnostics on malformed/unreadable settings. No repository/workspace/domain settings write, API-version rewrite or global configuration mutation.

3. **Transaction state.** Separate durable committed selection and current preview. Each requested candidate has monotonic generation + revision and membership version; serialize visible commits. prepare is side-effect-free for every required ready root/portal/native/frame/native-window participant and returns a bounded prepared handle. Late results dispose without commit. New/removing participant invalidates the prepared membership and forces safe reprepare or cancellation; an unready required editor does not silently opt out. Preview applies one snapshot but performs no settings write. Enter commits the selected preview only after required participants acknowledge; Esc/outside/opener cancel and window close restore the last committed snapshot, not a superseded preview. C supersedes late A/B at every async boundary, including the persistence queue; old CAS cannot write after C. Persistence occurs only after all presentation participants commit; failure triggers verified rollback. emit onDidChangeTheme only once success is authoritative; failure diagnostics stay accessible. Rollback failure is a real error/recovery state and blocks success, never swallowed.

4. **Presentation observation across the iframe.** A synchronous root style update alone does not prove cross-process atomicity. A separate validated prepare/commit/rollback message protocol carries origin, source identity, frame generation, transaction/revision and acknowledged applied phase. Stale/spoofed/wrong-source acknowledgements are rejected; timeout is failure. Do not share Draw.io repository/flow messages or modify vendor files. The injected bridge touches only frame DOM CSS and safe view-only canvas background/grid; it must not invoke model transactions, load/export paths, setCellStyles, metadata/route/endpoint changes or autosave. Parent/native graph adapters likewise must not recolor persisted node/edge paint or add undo entries. Use a short accessible visual commit barrier covering theme consumers while cross-frame commit/rollback acknowledgement is incomplete, so no partially updated scene is exposed. Keep the current candidate/previous presentation under the barrier; editors are not unmounted, recreated or flushed into new documents. The barrier announces one pending/failure state and retains/restores focus and all drafts. A failed rollback stays blocked with recovery diagnostics; do not reveal a mixed revision and call it success. The p95 clock includes preparation, barrier, adapter acknowledgement and persistent commit, not just root CSS mutation.

5. **Minimum migration / picker.** New scoped theme-consumers.css, activated only by the owned runtime root marker, maps existing eight shell aliases to canonical roles and covers shell/status/palette/overlays/native controls, current row/control density and the new picker. Preserve titlebar/activity/tab/breadcrumb/status geometry for the old tested viewports in this P01; later shell migration owns common-shell geometry redesign. Keep the existing Frade mark/Codicon/brand. Controls use semantic variables, focus >=2px, labelled native controls, Light/Dark/HC plus independent density and coarse targets. Existing hard-coded feature styling that remains outside the selected consumer selectors is listed as legacy, not advertised as fully migrated. Record exact selector/property surface inventory before implementation; any expansion beyond the named consumer categories requires review. No mass file replacement or a new UI library. Add one optional command hook to the existing Workbench command list; a local scoped Ctrl+K Ctrl+T chord owner with IME/text-entry/picker guards, disposal and collision tests, rather than inventing a repository-wide command registry. Picker has group/active indicator, arrow preview, Enter/Esc/outside cancellation, focus management and truthful failures. Test density/reflow and preview across existing portal parking/movement without creating another overlay architecture.

6. **Exact legacy occurrence transition.** Production checker and its moved/context/new-literal rejection tests stay unchanged. Save original full edited source bytes and inventory as immutable evidence. For edited host files only, inventory may delete a literal actually replaced by a semantic-token expression, or update the logical span of the same unchanged occurrence shifted by the reviewed edit. Before/after literal value, context hash, source order/one-to-one identity, classification, reason and closing owner must match; no new literal or reclassification is permitted. No entries outside edited files, no whole-file/generated exemption, no broad baseline reset. Record every old/new entry and source hash; unaffected entries remain identical. This is a consumer-owned reviewed transition, not permission for later unreviewed moves. Scanner continues to reject subsequent moved/new/duplicated values. If a moved occurrence cannot be proven uniquely, stop and propose its actual migration; do not guess. Builtin/domain source data remains frozen.

## Coherent spec additions after acceptance

Keep all four existing requirement names/bodies/scenarios. Add these obligations without narrowing existing measurable coverage:

- **Presentation consumer isolation:** changes affect only view presentation; real JSON/XML bytes, model paint, routes/endpoints, selection, undo/redo stack and graph/iframe/editor identity remain unchanged. Scenario: native selection + domain colors; scenario: loaded Draw.io document while theme commits; scenario: spoofed/stale frame acknowledgement.
- **Scoped durable presentation settings:** fixed user/profile location, validated DTO/revisions, preview no write, startup/restart restore and explicit untrusted workspace opt-in. Scenario: commit/restart independent density; scenario: malformed persisted settings; scenario: authorized main frame versus child frame/path injection; scenario: persistence refusal/unknown-outcome recovery.
- **Observable transaction lifecycle:** no mixed revision is exposed under actual required participant failure/race; frame barrier is bounded and rollback failure is not success. Scenario: A/B settle after C; scenario: membership change during prepare; scenario: slow/refusing commit; scenario: rollback failure; scenario: window closes during preview.
- **Explicit scoped consumer adoption:** accepted P01 selectors/occurrence transitions are recorded, old historical oracles preserved, current Light/Dark/HC × density evidence and real keyboard/a11y/p95 outcomes required. Scenario: root/portal/frame all follow one current revision; scenario: inherited legacy span shift is individually proven; scenario: unknown/new literal still fails; scenario: missing real performance/visual evidence blocks closure.

Exact BDD example IDs and future canonical cases FUI-005(light/dark/HC), FUI-006/007/008/009 must be bound to the new P01 assertion sources and immutable source hashes. Add P01 resolver/transaction/security examples in its own durable feature/registry. Preserve the foundation's 28 bindings and 23 future declarations byte-for-byte; the P01 report identifies the newly executed owner coverage, without pretending its tests ran during foundation.
