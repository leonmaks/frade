## Exact requested decision

Authorize the following replacement guard algorithm within the already accepted first-party P02 Windows backend. It adds no root, protocol operation, write authority, dependency, elevation, SDK, generic filesystem API or executable extension capability. It changes ONLY post-bind desired-access selection for the outer directory chain and makes its preservation evidence mandatory. Existing Main presentation paths/schema/CAS/generation and P01 source/tests/evidence remain unchanged.

### Full initial binding and continuous identity

1. Keep the original fixed local NTFS/x64 volume-GUID and single-component checked walk with original full directory access and FILE_SHARE_READ. Reject reparse/special/case-sensitive/ambiguous roots or ancestors and incompatible preexisting writers/deleters. Outer ancestors are never created. A missing install-root may only be created by the original checked-parent bootstrap. Establish and validate the strong install-root handle and exclusive ordinary coordinator lease BEFORE any metadata handoff. This preserves the empty-parent/missing-root check/open boundary; no metadata-only initial walk or unpinned path check is allowed.
2. Capture each original outer directory's volume serial/file ID, expected volume-GUID final path, ordinary type and case-mode in owning session state. Root, lease and directories below root keep their original desired access, no-write/no-delete sharing and lifetime. This session state is transient guard evidence, never persisted domain state.
3. Acquire overlapping replacement handles for ALL outer directories, including the volume root directory but excluding the installation root: SYNCHRONIZE|FILE_READ_ATTRIBUTES only; remove FILE_LIST_DIRECTORY/READ_DATA; never request WRITE_DATA/DELETE. Keep FILE_SHARE_READ, synchronous/reparse-open semantics unchanged. Volume GUID directory reopen is tied to the same verified volume, not a raw device or arbitrary host path. Every other component is reopened relative to its STILL-held original checked parent; no absolute ancestor path fallback or unlocked chain gap.
4. Acquire and validate the complete replacement set while the complete original set and strong root/lease remain held. Compare both sides' original volume/file ID/final path/type/case-mode; revalidate full root/lease chain. Only after every comparison succeeds hand ownership of replacements to the session and close redundant old outer handles. Keep every original directory object continuously retained until disposal through its same-object replacement. Never use blanket Outer release; partial acquisition/check/close failure means unusable binding, no bind ACK/installer request and deterministic all-handle disposal. Strong installation-root and child/source handles never change access/share in this handoff.

### Required confinement after handoff

Metadata retention is NOT an independent writer/delete-denial claim. The supported guarantee remains: attempted ancestor replacement/mutation is refused or cannot redirect checked root-relative effects, with actual outside-root bytes unchanged. Strong install-root/child pins, kernel handle-relative addressing and repeated exact identity verification carry that guarantee. Before every later non-disposal operation verify original bound volume/ancestor/root identities, expected final paths/types/case modes and lease ownership. If any check changes/unsupported/uncertain, refuse before effect or remain in original held root, invalidate the session and never ACK a verified capability. Disposal must still release handles even if verification is no longer possible. No effect may address an outer metadata handle or sibling path. Native helper effects remain restricted to the same Main-authorized userData/extensions root; Main keeps its original independently authorized presentation file IO.

The old promise of denying WRITE/DELETE sharing remains fully operative for install-root/child/source/lease handles. For outside-root metadata handles it describes unchanged share arguments, not an assertion that those arguments alone forbid all metadata-parent opens. Updating this distinction is part of this decision, not a silent security reinterpretation. Any concrete attack that redirects effects or breaks continuous identity is a blocker; no tolerance, race exception or Node fallback is accepted.

### Owned-object enumeration repair without share relaxation

Root/child listing and checked recursive cleanup may reuse an exact already-held owned lease/directory/pending-file object when reopening it would conflict with its own shares. Require exact parent/component binding, enumeration file ID versus held identity, same volume, expected final path/type, ordinary/single-link constraints and original bounds. The owned coordinator lease is recognized only at the root by its exact held identity; a name alone never makes it trusted or deletable. Lease cannot be closed, released, reopened or removed to make listing pass. Cached borrowed handles remain borrowed; enumeration cannot dispose them or alter their sharing. Unknown entries are opened with the original strict checked-child semantics; reparse/special/hardlink/conflicting entries refuse. Cleanup still deletes only actual checked opened objects, retains protections/current/rollback bytes and reports locks honestly. No filtering-away unknown entries or weakening existing assertions.

## Alternatives considered

- Immediate-parent-only handoff: narrow PRE PASS, but it leaves the reproduced higher-ancestor Temp sibling EBUSY; insufficient.
- Keep current full lifetime READ_DATA pins: preserves current guard but blocks required Main persistence and unrelated sibling IO; not a completed installer.
- Release all outer handles or use Node path/check fallback: contradicts checked continuous identity/confinement; excluded.
- Add native operations to write Main presentation siblings: expands root/write authority and still leaves higher-ancestor sibling interference; not selected.

Selected approach requests overlapping same-object metadata retention only after original strong binding, preserving one root and all effects while proving confinement and ordinary sibling compatibility. If fresh PRE or attacks disprove it, return with the actual minimum necessary alternative rather than widening it automatically.
