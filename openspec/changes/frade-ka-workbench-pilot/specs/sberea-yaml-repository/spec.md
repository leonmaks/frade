# Spec Delta

## Purpose

Определяет адаптер sberea, позволяющий открыть существующий многофайловый KA как архитектурный репозиторий Frade и сохранять редактирование непосредственно в исходных YAML без потери данных.

## ADDED Requirements

### Requirement: KA-001 Complete rooted loading

Загрузчик SHALL обходить локальные imports от выбранного root.yaml, учитывать каждый достижимый файл один раз и публиковать все архитектурные записи с отчётом полноты. Служебные разделы SHALL быть доступны отдельным представлением и сохраняться. Недоступные imports, циклы, неверный YAML и дубликаты SHALL давать адресные диагностики; неполная загрузка MUST NOT объявляться успешной writable-сессией.

#### Scenario: Load supplied baseline

- **WHEN** открыт неизменённый набор KA, исследованный 2026-09-24
- **THEN** учтены 22 файла, 138 архитектурных записей 19 типов и отдельные разделы sber, без скрытого усечения до размера первой страницы

#### Scenario: Broken or unsafe import

- **WHEN** import отсутствует, образует цикл или выходит за разрешённый корень через путь либо символьную ссылку
- **THEN** пользователь видит причину неполноты, запись не разрешается и файлы остаются неизменными

### Requirement: KA-002 Stable identity and source ownership

Идентичность SHALL опираться на идентификатор репозитория и исходный ключ сущности, отдельно от имени, типа представления и пути файла. Ссылки SHALL разрешаться по идентификаторам, а происхождение SHALL позволять определить исходный файл и узел записи. Неоднозначное владение несколькими исходными записями MUST NOT разрешаться молчаливым слиянием.

#### Scenario: Rename and relocate

- **WHEN** изменено отображаемое имя или файл объекта перемещён с корректировкой imports
- **THEN** после перечитывания объект имеет ту же идентичность и существующие ссылки продолжают его определять

### Requirement: KA-003 Preservation-aware in-place save

Сохранение атрибутов SHALL изменять только принадлежащую объекту запись в исходном файле, сохраняя неизвестные атрибуты, комментарии, соседние записи, порядок и стиль неизменённых YAML-узлов, кодировку и переводы строк. Нетронутые файлы SHALL сохранять исходные байты. Чтение и сохранение без изменений MUST NOT перезаписывать файлы или материализовывать defaults. Неподдерживаемые YAML-конструкции SHALL диагностироваться до записи.

#### Scenario: Edit one nested value

- **WHEN** изменено одно вложенное поле карточки и выполнено сохранение
- **THEN** повторное открытие показывает новое значение, комментарии и остальные поля сохранены, а хеши всех остальных исходных файлов совпадают

#### Scenario: Unsupported alias mutation

- **WHEN** изменение затрагивает конструкцию YAML, для которой сохранность не гарантируется
- **THEN** сохранение отклонено с диагностикой, исходные байты и черновик пользователя сохранены

### Requirement: KA-004 Guarded recoverable writes

Запись SHALL проверять ревизии объекта, источника и схемы у границы фиксации, использовать подготовку и атомарную замену одного исходного файла и обнаруживать прерванные операции. Неподдерживаемая атомарная операция над несколькими файлами SHALL отклоняться до записи. Потеря подтверждения MUST NOT вызывать автоматический повтор. Save All SHALL явно показывать результат каждого независимого сохранения.

#### Scenario: External concurrent edit

- **WHEN** исходный файл изменился после открытия карточки
- **THEN** устаревшее сохранение сообщает конфликт и не перезаписывает внешний файл

#### Scenario: Interrupted save

- **WHEN** процесс завершается во время фиксации и репозиторий открывают снова
- **THEN** доступна целостная подтверждённая версия либо диагностика восстановления с сохранёнными материалами операции, без ложного сообщения об успехе

### Requirement: KA-005 External diagnostics and safe repair

Исходные семантические ошибки SHALL быть видимы без исключения объектов из навигации. Явный профиль sberea SHALL разрешать исправления и изменения, не добавляющие и не усугубляющие ошибки, относительно проверенного baseline на одной ревизии. Новые ошибки изменённых полей или зависимостей SHALL блокировать запись. Отсутствующие внешние ссылки SHALL сохраняться; фиктивные целевые объекты MUST NOT создаваться. Строгая политика native-репозиториев MUST NOT ослабляться.

#### Scenario: Existing unresolved software reference

- **WHEN** пользователь меняет описание объекта, сохраняя его исходную неразрешённую ссылку на ПО
- **THEN** ссылка и диагностика сохранены, а изменение разрешено только при отсутствии новых или усиленных ошибок всего затронутого состояния

#### Scenario: Introduce an invalid reference

- **WHEN** пользователь заменяет ссылку новым отсутствующим идентификатором
- **THEN** сохранение отклонено с указанием поля, а исходный файл не изменён

### Requirement: SB-001 Explicit adapter selection and extensibility

Вид репозитория SHALL называться sberea и выбираться для конкретного корня workspace. Общий интерфейс SHALL поддерживать независимые адаптеры других YAML-форматов; расширение yaml MUST NOT автоматически означать sberea. Неизвестный адаптер SHALL давать диагностику своего корня без подстановки другого формата.

#### Scenario: Different formats in one workspace

- **WHEN** в workspace добавлены sberea и native YAML репозитории
- **THEN** каждый открывается своим адаптером и сохраняется в своём формате, а общие UI/Core не требуют sberea-специфичного поведения

#### Scenario: Unregistered adapter

- **WHEN** сохранённый корень требует незарегистрированный адаптер
- **THEN** этот корень показывает проблему подключения, остальные корни работают и данные не конвертируются
