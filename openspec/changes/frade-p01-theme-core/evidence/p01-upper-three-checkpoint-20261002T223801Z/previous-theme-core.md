## Ownership and API

The portable leaf modules in packages/ui-workspace/src/design/theme/ have no React, DOM, Electron, Node or repository imports. Main may import the explicit ./design/theme/types, /registry, /contrast and /resolver package exports without importing the Workbench barrel. Registry is an immutable in-memory data snapshot, not the P02 transactional installer. Keep document/domain paint separate from view presentation.

createThemeRegistry(descriptors) always supplies frade.builtin/light, frade.builtin/dark and frade.builtin/high-contrast offline. Native descriptor anatomy is id, label, kind, colors and optional enabled. Stable IDs use publisher.name/local; labels do not determine identity. Builtin IDs are reserved. Duplicate IDs retain the first descriptor with a diagnostic. Accessor/custom-prototype records, malformed fields and non-HEX6 known colors are rejected; unknown roles are diagnosed and ignored. No CSS expression, URL or arbitrary property is injected.

resolveTheme({ registry, selection, environment, overrides, revision }) returns a copied, deeply frozen snapshot: stable id, label, effective kind, independent density, revision, 31 complete HEX6 colors, final effectiveColors, forcedColors, status, repairPasses, issues and compatibility. Inputs and generated tokens are neither mutated nor frozen. Registry lookup/list output is immutable; no mutable map is exposed.

selection defaults to mode System, compact density and the matching builtin preferred ID for each kind. Explicit Light/Dark/HC wins over OS scheme and HC preference. System follows OS HC preference first, then dark/light. Forced colors is a final view projection even for explicit Light; it does not rewrite HEX6 colors or selection. Invalid/stale/disabled/wrong-kind preferred IDs fall back to the corresponding builtin with an explicit diagnostic.

Override order is builtin, enabled selected native palette, global user roles, current ThemeId user roles and explicitly opted-in workspace roles. Without workspaceEnabled: true, workspace roles are ignored. The resolver performs no IO and never installs, reads or grants execution to workspace packages.

## Portable transaction service

createPresentationService receives an initial validated snapshot/durable selection, session identity, a PresentationHost and a PresentationBarrier. Its register operation hides a joining participant immediately. ready resolves only after side-effect-free prepare and an exact subsequent applied-paint ACK for the current visible revision. Disposal invalidates membership/generation; hidden joins cannot reveal a previous transition. preview/commit/cancel return explicit outcomes; subscribe reports exactly did-preview/did-change/did-cancel or failure/recovery-blocked. state separates visible snapshot, committed snapshot, preview and authoritative durable revision. Inputs are copied/frozen and candidate snapshot revisions are owned by the service.

States are IDLE, PREPARING, READY, BARRIER_AWAIT_PAINT, APPLYING, PERSISTING, RECONCILING_UNKNOWN, COMPENSATING, PUBLISHED, CANCELING and RECOVERY_BLOCKED. READY is a synchronous checked handoff, not an async yield point. Each phase envelope carries version1, session/request/transaction, host intent generation, snapshot revision, membership and exact phase. Participant ACKs additionally carry participant identity/generation and painted:true; an unknown field, mismatch or obsolete membership is rejected. An adapter must check AbortSignal/generation before any late mutation and acknowledge only after actual subsequent paint. A callback/message receipt is insufficient.

The view queue serializes preparation, application and restoration while announceIntent is accepted before prepare. Superseded candidates cannot publish success. Prepare/apply/rollback limits are 2 seconds; host write/readback, intent ownership and reconciliation limits are 5 seconds. Timed-out prepare handles are disposed; no timeout is performance evidence. The barrier must paint a complete neutral client-area curtain before any apply and must stay covered through host durability, compensation and the single allowed membership reprepare. Preview/cancel perform no persist call. Cancel during an in-flight rename waits for reconciliation before returning, allowing the existing close/dirty-work guard to resume safely.

PresentationHost owns monotonic accepted generations and the serialized atomic-rename/readback/CAS queue. The service's persist call supplies the current generation and last authoritative durable revision; an ACK must match transaction/generation/selection and advance revision. Unknown outcomes or invalidations require host-owned reconciliation to the last published selection. Compensation uses the current accepted owner, restores all required participant snapshots and rejects changed membership before reveal. A compensation/readback or rollback refusal keeps the curtain in RECOVERY_BLOCKED. recover announces a fresh owner, proves durable reconciliation and all restored paints, then returns CANCELED; failure remains covered. New preview/commit attempts cannot bypass recovery.

The service has no filesystem, Electron, DOM, repository, document, selection or undo mutation APIs. Controlled tests use explicit view participants and separate dirty-document fixtures to assert preserved bytes/drafts/selection/undo, view snapshots, durable state and event ownership. Twenty-one P01-TX scenario declarations expand to 29 behavior cases; a separate integrity case checks exact assertion hashes. Additional named lifecycle and observer fault assertions execute in the same file. They execute in test:bdd together with the five pure P01-RES stories and existing bundle-flows. Host mocks and a painted-barrier fake verify the portable protocol only. Main queue/filesystem faults, actual client-area paint, frame security, bootstrap and real native/XML/model oracles remain required desktop evidence; these controlled results do not close task2.4 runtime-state coverage or task2.5 matrix evidence.

Named onWillChangeTheme({previous,candidate,revision}), onDidChangeTheme({snapshot}) and onThemeChangeFailed({reason,revision}) expose copied immutable data and return disposers. Will fires before the first prepare of a current request; did covers successful preview/commit/cancel and failed covers explicit refusal/recovery. Subscriber exceptions are retained as Observer failure diagnostics in state; they cannot change authoritative durable publication or mutate dirty-editor fixtures through these event payloads.

## Frame paint ownership

An inactive or occluded cross-origin iframe can throttle RAF.
